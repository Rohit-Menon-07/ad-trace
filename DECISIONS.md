# DECISIONS.md

Deviations from docs/SPEC.md and choices made where it was ambiguous. One line each: decision, then reason. Newest at the bottom.

## Prompt 1: scaffold + frontend shell

1. **Raw file name.** The real file is `data/raw/AD Notice of Proposed Rulemaking (AD NPRM).xlsx` (spaces and parentheses), not the underscored name in SPEC §2. `config.yaml` points at the real name. *Reason: match what is on disk; don't rename source data.*
2. **`RecordCard` and `ExcludedRecord` defined by us.** SPEC §7 uses them but doesn't define them. Fields are in `frontend/src/types/api.ts`. RecordCard holds status, comment period, lineage, models, model-list confidence and retrieval score. ExcludedRecord holds record id, docket, rule id and reason. *Reason: smallest shape that covers the UI spec in §8.*
3. **Extra API types defined:** `LineageEdge`, `RecordDetail` (for `/api/records/{id}`), `MetaResponse`, `CoverageReport`, `EvalResults`. *Reason: SPEC lists these endpoints without response schemas; the backend must match these types or update them.*
4. **No count of dropped claims in `SearchResponse`.** The UI reads `trace[S7].details.claims_dropped` for the "N claims removed" notice. *Reason: no schema change needed, and the code-generated trace already carries it.*
5. **Reason-code copy (title and suggested next action) lives in the frontend** (`components/reasonCodes.ts`). The codes themselves still come only from the backend. *Reason: the refusal card needs a "next action" (§8), but SearchResponse has no field for it; this is UI text, not a decision.*
6. **Source drawer is a fixed right column, not an overlay.** On narrow screens it stacks below the result. *Reason: §8 says "Right: source drawer"; a fixed column is simpler and works with the keyboard (Esc closes it, focus moves to it).*
7. **No router.** Search, Coverage and Evaluation are switched with local state. *Reason: react-router is not in the allowed stack.*
8. **Tailwind v4** (`@tailwindcss/vite`), with class-based dark mode via `@custom-variant`. *Reason: current major version; no PostCSS config needed.*
9. **MOCK labelling.** Mock records use ids `MOCK-R000n`, dockets `MOCK-FAA-…` and citations `MOCK 91 FR …`, with `url: null`. A fuchsia dashed MOCK badge appears in the header, on every mock response, in the source drawer and on Coverage/Evaluation. *Reason: fake data must never look like a real FAA notice.*
10. **Mock evaluation numbers are placeholders.** The Evaluation page shows a "MOCK placeholder numbers. Nothing has been measured" alert. *Reason: the tables must exist now, but no metric has been measured.*
11. **Mock citations are checked at load time.** `mockCite()` throws if a quote is not a substring of its sentence (mirrors H4). *Reason: stops mock quotes drifting from their sources.*
12. **Clarification chip in MOCK mode** fills the model field and serves the "answered" scenario. The real backend will re-run the pipeline. *Reason: mocks can't compute; the behaviour is marked in code.*
13. **`config.yaml` `as_of: null` means "today at request time".** The resolved date is echoed in `SearchResponse.as_of` and in the audit log. *Reason: as_of defaults to today but stays visible and reproducible per request.*
14. **Generated data is git-ignored:** `data/raw/`, `data/processed/*`, `data/index/*`, `logs/*`, and `.env` at any depth (including the existing `data/.env`). *Reason: the source file is not redistributed, derived files are rebuilt by `make ingest`, and logs contain user queries.*
15. **Makefile written, but `make` is not installed on the dev machine (Windows).** Run the commands directly; CLAUDE.md says so. Backend targets in the Makefile are placeholders until the backend exists. *Reason: keep the repo standard without blocking work.*
16. **Applicability verdict for a "series" designation (e.g. "A330-200 series") is UNDETERMINED in the mocks.** It is not treated as APPLICABLE. *Reason: the conservative reading of SPEC S4; the backend will apply the same rule.*

## Prompt 2: typed API contract + mock backend

17. **TS types are generated by our own small JSON Schema → TS converter** (`backend/app/export_types.py`), not by `json-schema-to-typescript`. *Reason: the drift test stays pure pytest with no Node dependency; it only needs to cover the constructs our models produce.*
18. **Requests are generated in validation mode and responses in serialization mode** (`json_schema_serialization_defaults_required`). Request fields with defaults are optional in TS; response fields are always present. *Reason: matches what each side actually sends.*
19. **`SearchResponse.reason_code` is typed `ReasonCode | None` (a closed Literal), not `str | None` as in SPEC §7.** *Reason: stricter. The backend cannot emit a code the UI doesn't know.*
20. **All API models use `extra="forbid"`.** *Reason: unknown request fields get a 422 rather than being silently ignored.*
21. **MOCK search routing (`mocks.choose_scenario`)** uses form fields before keywords:
    - "torque", "part number" or "A350-2000" → refused;
    - a family-only model such as "A330" → needs_clarification;
    - an A320 model, a serial, or "MSN" → partial;
    - anything else → answered.

    *Reason: clicking a clarification chip sets the model and must reach the answered scenario.*
22. **Mock responses get a fresh `MOCK-req-xxxxxxxx` request id per call; their `as_of` stays fixed at 2026-10-31.** *Reason: feedback needs unique ids, and the mock comment-period statuses were computed for that date.*
23. **`/api/eval/latest` serves `data/eval/results.json` if it exists, otherwise the MOCK placeholder.** `/api/feedback` is real and appends to `logs/feedback.jsonl`. *Reason: forward-compatible; there is nothing to mock in feedback.*
24. **The scenario switcher is now a set of dev presets that fill the form and call the real API.** It shows only under `vite dev` with `VITE_SCENARIO_SWITCHER=1` (committed `frontend/.env.development`; no secrets). *Reason: "keep the switcher behind a dev flag", while the response still comes from the backend.*
25. **The Makefile delegates to `scripts/tasks.py`, which runs uvicorn and Vite together** and stops both process trees on exit. *Reason: GNU make isn't on the dev box; `python scripts/tasks.py X` is exactly `make X`.*
26. **Frontend mock data moved to `backend/app/mocks.py`.** `frontend/src/mocks/` now holds only the request presets. *Reason: one copy of the MOCK data, served through the real contract.*

## Prompt 3: ingestion and cleaning (items marked REVIEW need a human decision)

27. **The CLI is `python -m backend.app.ingest.run`, not `python -m app.ingest.run`.** *Reason: the package is `backend.app`; `make ingest` calls it.*
28. **The DB lives at `data/processed/adtrace.db`** (config `data.sqlite_path` updated from `data/index/adtrace.sqlite`). *Reason: the Prompt 3 instruction.*
29. **Sentence ids are 1-based (`R0001#s1`); `ingest_meta.sentence_id_base = 1`.** The Prompt 2 MOCK records still use `#s0` and go away with the mocks. *Reason: the Prompt 3 instruction.*
30. **The workbook is read with `dtype=str, keep_default_na=False`.** Raw cells are stored exactly as read (`raw_*`); only empty cells become NULL. *Reason: pandas would otherwise turn text like "NA" or "None" into null.*
31. **REVIEW. A literal two-character backslash-n in 17 summaries is treated as whitespace** in cleaned text; raw is unchanged. *Reason: it's an export artifact that otherwise appears inside sentences.*
32. **REVIEW. PDF artifacts such as "AD 2024- 05-13" and "PC- 6/A-H1" (a space inside an identifier) are NOT repaired.** *Reason: rewriting identifiers is guessing; Prompt 4 extraction must tolerate them.*
33. **The `[ouml]`-style GPO entities in summaries are left as is.** *Reason: they are verbatim source text, and quotes must stay substrings of it.*
34. **Dates are strict `M/D/YYYY` with calendar validation; anything else becomes null and is logged.** Result: 0 unparseable, 4 missing Comments Due Date.
35. **REVIEW. `fr_citation` = "<volume> FR <first page>" only when the Citation contains "Volume N".** 12 rows from 2008–2010 ("Federal Register: July 21, 2010") get null; `citation_text` and `pages` are still stored. *Reason: deriving the volume from the year would be inference.*
36. **Make cells that list several makes (`A | B`, 5 rows) are split.** Each part is canonicalised and stored in `record_makes`; `records.make_canonical` joins them with ` | `. *Reason: a filter on any one listed make must match.*
37. **Canonical display name = the most frequent raw spelling in a normalised-key group** (ties: longer, then alphabetical). *Reason: deterministic, and the name users see most often.*
38. **Explicit merges beyond the key rule:**
    - "Airbus Helicopters Deutschland GmbH (AHD)" → "Airbus Helicopters Deutschland GmbH";
    - "Erickson Air-Crane Incorporated DBA Erickson Air-Crane" → "Erickson Air-Crane Incorporated".

    *Reason: the same name plus an abbreviation or DBA suffix.*
39. **REVIEW. Plain "Airbus" (15 rows): none has "Airbus SAS" in its Subject Heading, so all 15 stay "Airbus"** (family Airbus). "Airbus Industrie" (2 rows, 2004 era) also stays separate. Neither was merged into Airbus SAS, per the rule.
40. **REVIEW. Likely same-entity pairs were NOT merged because no rule covers them:** Embraer/Embraer S.A., Cessna/Cessna Aircraft Company, Piper/Piper Aircraft Inc., Gulfstream Aerospace Corporation/LP, the Bell Textron variants, the Pratt & Whitney variants, GE/"GE Aerospace", BAE Systems variants, Eurocopter (the predecessor of Airbus Helicopters). The full list is in docs/make_audit.md. *Reason: the conservative default. Retrieval should use make_family or fuzzy linking so these don't hide records.*
41. **3 rows with no Make stay null.** They are not inferred from the Subject Heading. *Reason: no guessing; listed in make_audit.md.*
42. **REVIEW. A new docket class `revision_series` (93 groups, 194 rows) was added** beside exact_duplicate / multi_product / correction. Most same-docket groups are NPRM → supplemental/revised NPRM → withdrawal publications, not duplicates. *Reason: the three-class brief misdescribes the data; this lineage drives "latest version" logic in Prompt 4.*
43. **An exact duplicate means the same docket plus identical make_raw, model_raw, subject_heading and summary.** Classes are checked in the order correction, exact_duplicate, multi_product, revision_series.
44. **REVIEW. One exact duplicate: R0195 (issued 2021-01-20) is marked `duplicate_of` R0277 (2011-01-27), docket FAA-2011-0099.** The earliest copy is kept. The FR pages differ, so this may be a genuine republication. Nothing is deleted.
45. **`multi_product` compares per-row canonical make sets** (or two different non-empty Model values). A docket where only one row has a Model filled is a revision_series. Result: 5 groups, including real conflicts (Boeing 777 vs Dowty propellers in FAA-2011-0033) and type-certificate transfers (Bombardier → De Havilland).
46. **Correction rows (4, docket ends in `R1` or Comments mention an OFR correction) record their base docket in a note.** None of the base dockets is in the dataset.
47. **Splitter rule: a protected abbreviation (U.S., No., Inc., Ltd., Co., S.A., S.p.A., Jr., …) does not end a sentence unless the next word is a strong starter ("This", "The", "We", …).** Periods inside matched brackets never split; unmatched brackets are ignored. *Reason: handles "Bombardier, Inc., Model" and "Textron Inc. This proposed AD" alike. On this dataset the override never fires.*
48. **Ingest regenerates `configs/alias_make.yaml`, `docs/make_audit.md` and `docs/duplicates_audit.md` deterministically on every run**, and builds the DB in a temp file that is atomically swapped in. *Reason: idempotent; rules are reviewed in code, and the yaml is the generated view of them.*

## Prompt 4: rule-based extraction with provenance (items marked REVIEW need a human decision)

49. **`make ingest` = ingest → extract on the temp DB → atomic swap.** A failed extraction never leaves a half-built DB. `python -m backend.app.extract.run` re-runs extraction alone; it drops and recreates its own tables.
50. **Span offsets:** `source=summary` spans are offsets into the Summary; `source=comments` spans are offsets into the Comments text; `source=column` spans are null. *Reason: SPEC only defines Summary offsets, and Comments must stay traceable too.*
51. **REVIEW. `family()` = the part before the first hyphen, but if that part has no digit (DC, BD, EMB, P, MBB) the next segment is included:** DC-9-81 → DC-9, BD-700-2A12 → BD-700, EMB-545 → EMB-545. *Reason: the literal rule makes "DC", "BD" and "P" families, which merges unrelated aircraft.*
52. **REVIEW. Suffix expansion uses the base before the LAST hyphen of the first full designator** ("DC-9-81, -82" → DC-9-82), not the first. It is identical for A330-243 / 777-200. *Reason: the first-hyphen rule gives "DC-82".*
53. **REVIEW. `norm_model` glues letters to numbers only for letter groups of at most 4 characters:** "AS 365 N2" → AS365N2 and "A300 B4-603" → A300B4-603, but "A330-200 Freighter" stays "A330-200 FREIGHTER". "SA-365N" and "SA365N" stay different (hyphens are kept), and "Gulfstream G150" ≠ "G150". *Reason: the literal rule produced "200FREIGHTER". Linking in S1 must handle the remaining variants.*
54. **REVIEW. "737-600, -700, … and 900ER" (a source typo with no dash) gives "900ER" as LOW (`model.summary.orphan_suffix`), not 737-900ER.** *Reason: no guessing; LOW models don't count as an extracted list.*
55. **Model column text without a digit ("radio (also known as radar) altimeter") is LOW `model.column.nondesignator` with model = null.** All-caps hyphenated codes without digits (G-IV, GIV-X, GV-SP) ARE accepted as designators.
56. **Added `model.summary.postfix`:** "PW210A and PW210S model turboshaft engines" and "S-76 model helicopters" (lowercase "model" after the list). *Reason: 8 real extractions the prefix rule cannot see.*
57. **Engine models named in an aircraft record ("767 airplanes equipped with GE Model CF6…") are kept**, with `value.product = "engines"`. *Reason: they are cited in the record; S4 can filter by product.*
58. **REVIEW. `applies_all_of_family` is emitted per family of every model in an "all … Model X" list**, so "all … Model AS350B3" gives family AS350B3. For hyphenless designators the family equals the model, so "all" means all serials of that model. *Reason: the literal "family" wording only makes sense for series lists. S4 must treat it as "all serials of the listed models".*
59. **Serial ranges/lists: NONE exist in the dataset** (0 "X through Y", 0 MSN/S-N numbers). The rules are implemented and tested on SYNTHETIC text only, with REAL negative tests. "certain serial numbers" is not a constraint. *Reason: the brief expected ~19; those summaries only say "certain serial numbers".*
60. **REVIEW. `svcinfo.defined` requires products/serial numbers to be "identified/listed/specified in" service information or a service bulletin; it fires on 0 real records.** "As specified in an EASA AD" (actions) and "unsafe condition identified in the NPRM" are deliberately excluded. *Reason: loose phrases gave only false positives.*
61. **Added rules beyond the brief:**
    - `withdraw.notice`: 123 records are themselves withdrawal notices.
    - `extension.notice`: 4 records announce a comment-period extension.
    - `continue.retain`: "retain the requirements from AD X", MEDIUM.
    - `applicability.add` / `applicability.remove`: MEDIUM.
    - `supersede.unnumbered`: "supersede an existing AD", LOW, no edge.
    - `supersede.negated`: "decided not to supersede", LOW.

    *Reason: needed for status and lineage; all are visible by rule_id.*
62. **AD numbers tolerate PDF spaces ("AD 2024- 05-13" → 2024-05-13) and keep revision suffixes ("72-14-08 R1").** Supersession captures every AD in the clause, including "…; and AD Y, which…".
63. **Lineage edges:**
    - supersedes/continues target "AD n" and are never marked in-dataset (the AD Number column holds each NPRM's final AD number; none is cited).
    - withdraws targets same-docket records issued no later than the notice.
    - comment_extension notices target the other records in their docket.
    - shares_docket edges are written for every same-docket pair.
    - applicability_change targets the record's first superseded/continued AD, else its docket.
64. **REVIEW. R0159's sheet already shows the extended due date (12/09/2024)**, so the extension changes nothing there. `comments_due_effective` logic is proven on a SYNTHETIC row.
65. **New table `record_flags`** (per-record model list + confidence, families, all-families, certain, serial_resolved, svcinfo, is_withdrawal_notice, withdrawn_by). *Reason: precomputed inputs for the S4 engine.*
66. **Coverage denominator = 430 non-duplicate records.** "Model list extracted" counts HIGH or MEDIUM only. `coverage_report.json` uses the CoverageReport API schema; `generated_at` is the source sha1 (not a timestamp), so it stays idempotent.
67. **`docs/extraction_spotcheck.csv` is 25 uniformly random extractions (seed 20261031), written only if the file is absent**, so re-ingesting never overwrites your Y/N labels. Because it is uniform, ~25% are trivial Model-column rows. Precision: `python scripts/spotcheck_precision.py` (with a Wilson 95% interval).
68. **Ruff E501 is ignored in `backend/tests/*`.** *Reason: golden tests embed verbatim real sentences.*
